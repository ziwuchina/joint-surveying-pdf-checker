# 联合测绘PDF报告检查系统

基于 PyQt5 的联合测绘 PDF 报告自动化检查工具，支持 PDF 解析、EDB 数据库对比、面积逻辑校验和标注版 PDF 生成。

## 功能概览

### PDF 内部检查
- **竖向检查**：分项面积合计 = 总面积（许可值/测量值/计容面积）
- **横向检查**：分层表 vs 单元表 vs 汇总表 vs 规划指标交叉比对
- **分摊系数**：验证分摊系数 = 总分摊 / 总套内
- **许可vs测量**：全量对比所有建筑的许可值与测量值差异（阈值：ERROR ≥200㎡且≥5%，WARN ≥50㎡且≥1%）
- **特殊检查**：配套设施面积归属错误检测、不动产总面积 vs 规划总面积饰面差异

### EDB 数据库对比检查（关联 .edb 文件后启用）
- **EDB 内部一致性**：检测 EDB 数据库中分项合计 ≠ 总面积等源数据错误
- **EDB vs PDF 数值对比**：逐项比对 EDB 源数据与 PDF 提取值
- **EDB vs PDF 完整性**：检测 PDF 遗漏的建筑、楼层
- **EDB vs PDF 单元面积**：对比 EDB 面积块表"车间"数据与 PDF 单元面积表，检测 VBS 脚本输出异常

### 标注版 PDF 生成
- 在原 PDF 页面底部标注错误/警告信息
- 末尾自动追加检查结果汇总页

## 项目结构

```
checker/
├── main.py              # PyQt5 GUI 主程序
├── pdf_parser.py        # PDF 报告解析器（pymupdf）
├── checker.py           # 检查规则引擎（竖向/横向/分摊/许可vs测量/EDB对比）
├── edb_reader.py        # EDB 数据库读取器（ADODB/ACE OLEDB）
├── models.py            # 数据模型定义（Decimal 精度运算）
├── 启动检查系统.bat      # 批处理启动脚本
├── 启动检查系统.vbs      # VBS 启动脚本（无 CMD 窗口）
└── README.md
```

## 环境要求

- **Python 3.12+**
- **Windows**（依赖 ADODB/ACE OLEDB 读取 EDB）
- Microsoft Access Database Engine（ACE OLEDB 12.0）

### Python 依赖

```bash
pip install PyQt5 pymupdf pywin32
```

## 使用方法

### 方式一：VBS 启动（推荐，无 CMD 窗口）
双击 `启动检查系统.vbs`

### 方式二：批处理启动
双击 `启动检查系统.bat`

### 方式三：命令行启动
```bash
python main.py
```

### 操作流程

1. 点击 **「打开PDF报告」** 选择待检查的 PDF 文件
2. 点击 **「关联EDB数据库」** 选择对应的 .edb 文件（可选，启用 EDB 对比检查）
3. 系统自动解析并执行检查
4. 查看检查结果树（按类别分组，支持点击查看详情和计算过程）
5. 点击 **「生成标注版PDF」** 导出带错误标注的 PDF

## 检查结果说明

| 状态 | 含义 |
|------|------|
| ✓ 通过 | 检查项通过 |
| ✗ 错误 | 数据不一致，需立即修正 |
| ⚠ 警告 | 数据存在差异，建议核实 |

### 检查类别

| 类别 | 说明 |
|------|------|
| 竖向-建筑面积汇总表 | 分项面积合计 vs 总面积 |
| 竖向-计容面积汇总表 | 计容面积分项合计 vs 计容总面积 |
| 竖向-分层面积表 | 逐层面积合计 vs 总计 |
| 竖向-分摊说明 | 套内+分摊 vs 总建筑 |
| 横向-分层vs单元 | 分层表总套内 vs 单元表套内合计 |
| 横向-分层vs汇总表 | 分层总面积 vs 汇总表(测量+饰面) |
| 横向-分摊说明vs分层 | 分摊说明数据 vs 分层表数据 |
| 横向-汇总表vs指标 | 各栋合计 vs 规划指标 |
| 分摊系数 | 系数 = 总分摊 / 总套内 |
| 许可vs测量 | 许可值与测量值差异检测 |
| 特殊检查 | 配套设施归属、饰面差异 |
| EDB内部一致性 | EDB 数据库源数据矛盾检测 |
| EDB对比-数值 | EDB vs PDF 逐项数值比对 |
| EDB对比-完整性 | PDF 遗漏建筑/楼层检测 |
| EDB对比-单元面积 | EDB 面积块"车间" vs PDF 单元面积表 |

## 技术要点

- **Decimal 精度运算**：所有面积计算使用 Python `Decimal` 类型，避免浮点误差
- **三层检查架构**：PDF 内部检查 → EDB 内部一致性 → EDB-PDF 对比
- **EDB 作为 Ground Truth**：EPS 专用 .edb 数据库包含完整源数据，用于验证 PDF 输出的完整性和准确性
- **VBS 输出缺陷检测**：通过 EDB 面积块表数据与 PDF 单元面积表对比，自动检测 VBS 脚本因建筑结构差异（如每层单元数不同）导致的数据读取错位

## 通用化配置（新项目无需改代码）

不同项目的建筑命名、功能分类、表格标签可能不同。系统通过 `rules.json` 配置文件驱动，新项目只需调整配置：

| 配置节 | 用途 | 示例 |
|--------|------|------|
| `建筑名称别名` | 建筑名不同叫法统一（如 "13座" vs "13 栋"） | `"13栋": ["13座", "13 座", "13号楼"]` |
| `子项功能分类` | 功能名 → 类别（roof/facility/basement/main），EDB 与 PDF 共用 | `"main": ["厂房", "商业", "住宅", ...]` |
| `分项名称别名` | EDB 与 PDF 对同一分项的不同叫法 | `"公共服务设施": ["公交首末站"]` |
| `楼层标签字段` | 分层明细标签归属（公建/套内/不分摊） | `"public": ["公建", "公共"]` |

匹配策略（内置，无需配置）：
- 建筑名称归一化：去空白、全角转半角、幢→栋、号楼→栋
- 模糊匹配 key：归一化后再去掉尾部量词（栋/座/号），"13栋"≈"13座"
- EDB-PDF 建筑差集、分项对比均使用归一化后的名称，避免命名差异误报

修改 `rules.json` 后重启检查系统即可生效（无需修改任何代码）。

## 数据来源

- **PDF 报告**：EPS 软件通过 VBS 脚本生成的房产测量资料簿
- **EDB 数据库**：EPS 软件专用 Access 数据库，包含建筑、分项、楼层、面积块等完整数据
